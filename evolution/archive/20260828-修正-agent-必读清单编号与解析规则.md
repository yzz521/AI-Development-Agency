# 提案：修正 Agent 必读清单编号与解析规则

## 背景与证据

`agents/backend/java-developer.md` 的"开始工作前必须读取"清单编号从 5 直接跳到 8（缺 6、7），且 `Requirements / API / DB Artifact` 等非文件项与文件项混排。后果：

- Agent 阅读时容易误判"漏读了 6、7 两项"。
- 工具（如 `agency use` / `scripts/validate.sh`）按文件路径正则解析必读引用时，非文件项会产生噪音。

## 现状问题

1. 编号不连续，破坏清单的"顺序可执行"语义。
2. 文件项与非文件项混排，无法机器解析。

## 建议变更

1. `java-developer.md` 必读清单重新连续编号。
2. 约定清单规范：文件项用 backtick 包裹且以 `agents/|rules/|context/|workflows/|contracts/|artifacts/|validation/|templates/` 或 `AGENTS.md` 开头；非文件项（如 `Requirements / API / DB Artifact`）移出编号清单，单独作为"输入材料"说明。

## 影响面

- 影响的 Agent：`agents/backend/java-developer.md`（其余 Agent 清单本身编号连续，仅需检查）
- 影响的 Rule / Workflow：无
- 兼容性：向后兼容（PATCH 级格式修正）
