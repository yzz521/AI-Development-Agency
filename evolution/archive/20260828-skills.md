# 提案：新增场景技能层 skills

## 背景与证据

ponytail 的技能族（`ponytail-review` / `ponytail-audit` / `ponytail-debt`）每个都是：显式触发描述 + 边界（只做什么、不做什么）+ 退出方式，即调即走、单一产出。

Agency 现状：`agents/` 的 28 个角色全是"全时段身份"（12 节长 Prompt）；一次会话内的轻量场景（"review 我这个改动"、"收割债务"、"查任务单")没有对应的轻量单位——要么套一个重角色，要么散在手册里。

## 现状问题

1. 无"即调即走"的轻量单位，小场景被重角色 Prompt 压扁。
2. 无"触发描述/边界/退出"纪律，Agent 容易在场景外越界（如审计时顺手改代码）。
3. 与 scripts/（命令）的关系未定义，能力散落。

## 建议变更

1. 新增 `skills/` 层：定义文档（Skill = 场景 → 过程 + 命令 的薄包装；不定义身份、不编排多角色、区别于 Agent/Workflow；可引用 scripts/ 命令）。
2. 首批 3 个示例技能：`debt`（收割 agency: 注释）、`task-audit`（交叉核对任务单）、`diff-review`（只审过度设计）。
3. 总控 `AGENTS.md` 补"角色纪律"：角色是身份、技能是场景工具；技能必须写触发/边界/退出；使用技能不改变当前角色。

## 影响面

- 影响的 Agent：无（角色不变）
- 影响的 Rule / Workflow：新增 `skills/` 目录；AGENTS.md 加一段纪律
- 兼容性：向后兼容（纯新增）
