# 全局沟通偏好接入指南

## 目的

Agency 的 `rules/communication.md` 是跨项目的通用表达规则；`profiles/default.md` 是个人偏好。两者不能混为一谈：

- **Rule**：所有接入 Agency 的项目都应遵守的表达质量标准。
- **Profile**：某个用户明确选择后才加载的个人偏好。
- **Skill**：按任务触发的工作流程，不适合承载每轮对话都要遵守的表达约束。

## 推荐接入方式

1. 项目内使用：确保项目根目录 `AGENTS.md` 已加载 Agency 路由。v2.3.0 起，`rules/communication.md` 进入常驻路由。
2. 个人偏好：在支持用户级指令 / profile 的工具中，将 `profiles/default.md` 的内容配置到该工具的用户级指令；也可以在会话开始时明确要求读取该文件。
3. 不要把 Profile 自动复制进每个项目，也不要把个人偏好写成所有团队成员必须遵守的规则。
4. 工具支持的全局配置位置不同，按对应工具当前版本的官方机制配置；不要假设一个文件能自动被所有工具发现。

## 能力边界

- 项目级 `AGENTS.md` 只对读取该文件的工具 / 会话生效。
- 用户级配置只对支持并已启用该配置的工具生效。
- ChatGPT 网页端、独立聊天窗口或未连接 Agency 的模型，不会因为文件存在于 GitHub 仓库就自动读取它。需要把偏好写入该产品支持的自定义指令，或在相关会话中提供文件内容。
- 规则能提高一致性，但不能保证每次输出都完全符合；应通过真实对话样例持续校正。

## 验收方式

用同一组问题分别测试接入前后：

- 简单事实问答：是否先给答案，避免长篇铺垫。
- 方案判断：是否先给推荐，再给关键理由。
- 操作任务：是否给出可执行步骤，而不是只讲原则。
- 信息不足：是否只问一个必要问题，不擅自补全事实。
- 用户明确要求详细报告：是否能展开，而不是机械压缩。
