# Skill: diff-review — 只审过度设计

## 触发

- "review 一下这个改动"
- "看看哪里过度设计了"
- "这个 diff 有没有能删的"

## 过程

1. 取待审 diff（当前未提交改动或指定范围）。
2. 只按以下标签审**过度设计 / 可删性**，一行一条、按"可删量"从大到小排序：
   - `delete`：可删的代码（死代码、重复、未使用）
   - `stdlib`：标准库可替代的手写实现
   - `native`：平台原生能力可替代的库
   - `yagni`：不需要的抽象 / 配置 / 脚手架
   - `shrink`：可显著缩短的冗长写法
3. 输出格式：`[标签] 文件:行号 — 一句说明`。

## 边界

- 不审正确性、性能、安全、可读性风格（那是其它审查的职责）。
- 不改代码——只输出清单。
- 不扩大到 diff 之外的重构建议。

## 退出

输出排序后的可删清单即结束；需要动手删除时另开任务。
