## 一、归属判定标准

判定只问一个问题：**这项资产需要「每次都生效」，还是「需要时才生效」，还是「必须被强制」？**

| 需要的语义 | 正确载体 | 强制力 |
|---|---|---|
| 每次都生效（红线、身份边界） | 根目录 `AGENTS.md` | 无（仅注入） |
| 按文件类型生效（技术栈规则） | `.cursor/rules/*.mdc`（Cursor 专有）| 无 |
| 需要时才生效（一次性动作） | `.agents/skills/*/SKILL.md` | 无 |
| 角色身份 | 各工具 agents 目录 | 无 |
| **必须被强制** | git hooks + CI | **有** |

关键判断：前四层都只是「降低违规概率」，**只有第五层有强制力**。存量数据已证明单靠注入不足（`团队推广方案.md` §1.2）。

## 三、跨工具落点

一份内容，三个落点，**生成而非复制**：

```text
业务仓库/
├── AGENTS.md          🟢 常驻红线（Cursor / Codex 自动读）
├── CLAUDE.md          → 软链到 AGENTS.md（Claude Code）
├── .agents/skills/    🟡 动作类技能（多工具通吃，厂商中立目录）
├── .cursor/rules/     🟡 条件加载（仅 Cursor 用户受益）
└── .githooks/ + CI    🔴 唯一有强制力的一层
```

已验证：本机同时存在 `~/.codex/skills`(94) / `~/.agents/skills`(94) / `~/.cursor/skills-cursor`(25) / `~/.claude/skills`(2)。其中 `.agents` 与 `.codex` inode 不同但内容完全相同 —— **现状是复制出来的两份，正是漂移来源**，故落点选厂商中立的 `.agents/`。
