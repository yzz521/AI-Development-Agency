# AI Development Agency 日常使用手册 v1.0

> 目标：把"中央 Agency + 项目 AGENTS.md + .ai/agency 入口"真正用进每天的工作，并让规则库持续自进化。

## 1. 一次性安装

```bash
# 1) 安装 agency 命令到 PATH（~/.local/bin 或 ~/bin）
./scripts/install-cli.sh

# 2) 验证
agency version          # → AI Development Agency v1.3 ...
agency help
```

### 批量初始化 workspace 下所有项目

```bash
cd ~/workspace/AI-Development-Agency
./scripts/init-all.sh ~/workspace          # 非递归：只扫一层
RECURSIVE=1 ./scripts/init-all.sh ~/workspace   # 递归扫描
```

每个项目会得到：

```text
项目/
├── AGENTS.md              # 已有则不覆盖
└── .ai/agency -> ../AI-Development-Agency   # 相对软链接，可随 workspace 整体搬家
```

## 2. 每天开工三件事

```bash
agency status .           # ① 检查当前项目接入是否正常（doctor）
agency list rules         # ② 看当前规范库有什么规则
agency use java-developer # ③ 组装今天要用的 Agent（角色 + 必读文件 + 建议流程）
```

在 AI Coding 工具（Codex / Reasonix / DeepSeek Harness）里开始任务前，让它：

1. 读项目 `AGENTS.md`；
2. 读 `.ai/agency/AGENTS.md`（总控）；
3. 按任务加载最小必要 Agent / Rule / Workflow（用 `agency use <agent>` 的输出）。

**核心原则：选择最小必要 Agent，不一次加载全部。**

## 3. 命令速查

| 命令 | 作用 |
| --- | --- |
| `agency status [dir]` | 检查项目接入（软链接 / AGENTS.md / 目录） |
| `agency init [dir]` | 初始化项目接入 |
| `agency list [agents\|rules\|workflows\|context]` | 列出规范库内容 |
| `agency use <agent>` | 组装打印 Agent 使用块（角色 + 必读文件 + 建议流程） |
| `agency search <关键词>` | 全库搜索 |
| `agency feedback ...` | 记录规则使用反馈 |
| `agency propose ...` | 创建规则改进提案 |
| `agency review` | 生成本轮自进化评审简报 |
| `agency validate` | 校验规范库完整性（本地门禁） |
| `agency changelog` / `agency version` | 查看版本与变更记录 |
| `agency update` | 拉取最新规范并刷新项目链接 |

## 4. 任务执行标准流程

```text
1. agency status . 确认接入
2. 读项目 AGENTS.md → .ai/agency/AGENTS.md
3. 判断任务风险等级（L1/L2/L3，见总控 §5）
4. agency use <主Agent>；必要时选 Review Agent
5. 按角色"开始工作前必须读取"清单加载 Rule / Context
6. 先读真实代码，再动手（最小改动，禁止无关重构）
7. 自检 + 验证（L2+ 至少一次 QA/Review）
8. 最终汇报（含"规则反馈"字段）
9. 有缺口 → agency feedback / agency propose
```

## 5. 自进化：让规则库自己长

### 反馈（每次任务后，30 秒）

```bash
agency feedback --kind rule_applied --project javert \
  --agent java-developer --task "xxx" --rule rules/java.md \
  --detail "规则 3 防止了 Map 滥用，本次直接生效"

# 遇到没有规则覆盖的情况：
agency feedback --kind rule_gap --project javert \
  --detail "SSE 重连场景没有规则约束，团队出现两种实现"
```

### 提案（反馈累积到值得固化时）

```bash
agency propose --type rule-add --title "新增 SSE 重连幂等规则" \
  --evidence "javert 项目 OCR 流水线：SSE 断开重连出现重复推送，无规则覆盖" \
  --impact "java-developer / ai-engineer"
```

### 评审（每周一次，10 分钟）

```bash
agency review      # 看简报：待评审提案 + 近期反馈 + 指标
```

由 `agency-curator` 按 `workflows/evolution-review.md` 执行：打回无证据的、合并有证据的、破坏性变更找你人工确认。合并后自动要求：validate 通过 → CHANGELOG → bump 版本 → 提案入 archive。

### 守门（提交前）

```bash
agency validate    # FAIL=0 才允许合并；CI 里也跑（.github/workflows/validate.yml）
```

## 6. 多工具统一

- **Codex**：进项目后让它读项目 AGENTS.md，再按任务加载 Agency 文件。
- **Reasonix**：把 Agent 定义作为角色/Profile 来源。
- **DeepSeek Harness**：见 `adapters/deepseek-harness.md`，本项目即示例（Javert 已接入）。

工具是运行层，Agency 是规范层 —— **不要把 Agent Prompt 复制到工具自己的配置目录**。

## 7. 常见问题

| 问题 | 解决 |
| --- | --- |
| 换电脑 / 移动 workspace | 相对软链接自动跟随，无需改项目；重新跑 `agency update` |
| 某个项目 AGENTS.md 被覆盖 | 不会：init 脚本已有文件不覆盖 |
| 规则库被改坏了 | `agency validate` 定位；规范变更一律走分支 + PR |
| 想加项目专属规则 | 写进项目自己的 AGENTS.md，不要塞中央 Agency |
| 提案没证据被打回 | 补 `--evidence`（项目 + 任务 + 观察），重新评审 |
