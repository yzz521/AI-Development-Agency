# AI Development Agency 日常使用手册 v1.0

> 目标：把"中央 Agency + 项目 AGENTS.md + .ai/agency 入口"真正用进每天的工作，并让规则库持续自进化。

## 1. 一次性安装

```bash
# 1) 安装 agency 命令到 PATH（~/.local/bin 或 ~/bin）
./scripts/install-cli.sh

# 2) 验证
agency version          # → AI Development Agency v1.6 ...
agency help
```

### 批量初始化 workspace 下所有项目

```bash
cd ~/workspace/AI-Development-Agency
./scripts/init-all.sh ~/workspace          # 非递归：只扫一层
RECURSIVE=1 ./scripts/init-all.sh ~/workspace   # 递归扫描
```

每个项目会得到：

```text
项目/
├── AGENTS.md              # 含规范路由段（已有文件不覆盖正文，会刷新路由段）
├── .cursor/rules/agency-router.mdc
├── .agents/skills/agency-route/
└── .ai/
    └── agency -> ../../AI-Development-Agency
```

## 2. 每天怎么用（不必记命令）

接入一次之后，**直接在 Cursor / Codex / Claude Code 里下任务**。规范路由靠：

1. 项目 `AGENTS.md` 里的「规范路由」段（多数工具自动读）
2. `.cursor/rules/agency-router.mdc`（Cursor 每次注入）
3. `.agents/skills/agency-route`（按写代码任务自动匹配）

不要先跑 `agency use`。CLI 只在你想核对「这次到底命中了哪些摘要」时用：

```bash
agency status .            # 检查接入
agency route --task "给审核加一个查询接口" --files Foo.java
```

**核心原则：只加载命中的规则摘要，不一次加载全部。**

## 2.1 怎么知道规范有没有被用到

这是三件不同的事，不要混成一句「触发了吗」。

| 你想确认的 | 能证明什么 | 怎么看 | 证明不了什么 |
| --- | --- | --- | --- |
| **A. 进没进上下文** | 工具有没有把路由段/规则塞进模型 | Cursor：项目 `.cursor/rules/agency-router.mdc` 是否 `alwaysApply`；会话里是否出现技能 `agency-route` 或 Read 了 `AGENTS.md` / `rules/*.md` | 模型有没有照着做 |
| **B. 模型认没认** | 模型是否声称完成了匹配 | 写代码回复的**第一行**应是 `agency-route: matched=... risk=... rules=... opened=... source=...` | 它是否真的读了摘要原文 |
| **C. 代码守没守** | 生成结果有没有违规 | `agency check`（增量）；hook / CI 才是强制 | 「这次刚好没违规」≠「以后都会守」 |
| **C. 代码守没守** | 生成结果有没有违规 | `agency check`（增量）；hook / CI 才是强制 | 「这次刚好没违规」≠「以后都会守」 |

Javert 的教训仍然成立：规范写进 `CLAUDE.md` 照样会出 `Map`。所以 **C 才是强制**；A/B 只降低漏读概率。

### 30 秒探测（不改代码）

对 AI 说：

```text
只做路由探测，不要改代码。任务：给审核加一个查询接口。
```

合格：第一行是 `agency-route:`，`matched` 说得通，写代码时 `opened=` 是真实打开过的语言/领域原文（探测可以 `opened=none`）。
不合格：没有这一行；或 `opened=` 写了没读过的文件。

用 CLI 对照（可选，不代替上面那行）：

```bash
agency route --task "给审核加一个查询接口" --files Foo.java
```

输出里同样有 `agency-route:` 行。两边对不上，以会话回执为准去追问模型。

### 事后留痕

```bash
agency task --title "..."     # 把回执抄进任务单「规范路由回执」
agency audit .                # 缺回执会 WARN；有回执会核对格式
```

`agency audit` **不能**证明「AI 真的读了规则正文」。它只能证明：任务单自洽、文件存在、回执格式对。深度抽查仍是打开那次会话，看有没有 Read 规则文件、第一行有没有回执。

## 2.2 门禁怎么做（强制层）

三层里**只有 hook + CI 有强制力**。注入和路由回执都不能代替它。

原则：

1. **只卡增量**，不卡存量。存量用 `agency check --all` 做台账，按模块清，不当提交开关。
2. **每条规则单独开关**（`agency-check.conf`）。默认只开误报低的三项：`java-map-object`、`sql-select-star`、`secret-hardcoded`。
3. **不要绑进每次 `agency init`**，避免没准备好的仓库被 hook 吓到。
4. 门禁文件不要放进被 gitignore 的 `.ai/`。

```bash
# 业务仓库落地一次（可提交）
agency check --install ~/workspace/你的项目

# 本机拦截暂存区
git config core.hooksPath .githooks   # 每个 clone 一次；同事不设也没关系，CI 仍拦

# 提交前 / CI
agency check --staged
agency check --base origin/main
```

GitLab / Jenkins 没有现成模板时，等价跑：`bash .agency-check/check.sh --base origin/main`。

Javert 专有规则（一律 POST、`ylzzjgdm`）不要当中央默认 on。魔法值、DTO 语义、医疗口径不做机检。

## 2.3 存量怎么清（不进同一道闸）

`agency check` 默认只卡增量，存量不会自己消失。不要把 `--all` 接到 hook/CI。

建议每月一次：

```bash
cd ~/workspace/你的项目
agency check --all 2>&1 | tee agency-stock-$(date +%Y%m).log
```

把命中按模块记台账，分 PR 清理。`agency debt` 收的是 `agency:` 简化注释，和机检存量不是一回事。

## 3. 命令速查

| 命令 | 作用 |
| --- | --- |
| `agency status` / `agency doctor` [dir] | 检查项目接入（软链接 / AGENTS.md / 目录） |
| `agency check [dir]` | 增量规范门禁（只卡 diff 新增行） |
| `agency check --install [dir]` | 写入 hook / CI / `.agency-check/`（可提交；不绑进 init） |
| `agency init [dir]` | 初始化项目接入 |
| `agency list [agents\|rules\|workflows\|context]` | 列出规范库内容 |
| `agency use <agent>` | 可选：组装完整角色 Prompt（日常写代码不必先跑） |
| `agency route ...` | 可选检查器：打印本次任务命中的规范摘要 |
| `agency route --install [dir]` | 把自动路由写入业务仓库（AGENTS.md 段 / Cursor 规则 / 技能） |
| `agency search <关键词>` | 全库搜索 |
| `agency require [--title] [dir]` | 创建需求单（提需求用，产物在项目 `.ai/requirements/`） |
| `agency task [--title] [dir]` | 创建任务单（AI 执行证据，产物在项目 `.ai/tasks/`） |
| `agency audit [dir]` | 交叉核对任务单，验证 AI 是否真实按规范执行 |
| `agency debt [dir]` | 收割 `agency:` 注释为债务台账（无升级路径标记 no-trigger） |
| `agency feedback ...` | 记录规则使用反馈 |
| `agency propose ...` | 创建规则改进提案 |
| `agency review` | 生成本轮自进化评审简报 |
| `agency validate` | 校验规范库完整性（本地门禁） |
| `agency changelog` / `agency version` | 查看版本与变更记录 |
| `agency update` | 拉取最新规范并刷新项目链接 |

## 4. 任务执行标准流程

### 0. 提需求（人做的事）

```bash
# 生成需求单（模板：templates/requirement.md）
agency require --title "新增规则查询接口"

# 编辑填写 5 要素：目标背景 / 需求内容 / 约束边界 / 验收标准 / 补充
# 填完把文件内容或路径交给 AI 执行
```

> 也可以不建文件，直接对 AI 说："需求：xxx。背景：xxx。约束：xxx。验收：xxx。"
> AI 收到后会先回"任务理解 + 风险等级 + 计划"让你确认，再动手。

### 1–9. AI 执行（标准流程）

```text
1. agency status . 确认接入
2. 读项目 AGENTS.md 的规范路由段（自动注入，不必先跑命令）
3. 判断任务风险等级（L1/L2/L3，见总控 §5）
4. 按命中摘要实现；`agency use <主Agent>` 仅在需要完整角色 Prompt 时可选
5. 按角色"开始工作前必须读取"清单加载 Rule / Context
6. 先读真实代码，再动手（最小改动，禁止无关重构）
7. 自检 + 验证（L2+ 至少一次 QA/Review）
8. 按风险汇报（L1 三行 / L2 短 / L3 完整表）
9. 有缺口/过时/违反 → agency feedback / agency propose；顺利的 L1/L2 不要走流程写反馈
```

### 10. 留证据（AI 必做，你随时可查）

```bash
# ① 生成任务单，如实填写：实际读取/修改的文件、验证命令与结果、规则反馈
agency task --title "新增规则查询接口"

# ② 交叉核对：读取文件是否存在、修改文件是否有变更痕迹、规则引用是否可解析
agency audit .
```

> **怎么知道 AI 是否真实使用了规范？** 见 §2.1。短答：第一行看 `agency-route:`（含 `opened=`）；`agency audit` 只核任务单；代码守规看 `agency check`。

## 5. 自进化：让规则库自己长

### 反馈（每次任务后，30 秒）

```bash
agency feedback --kind rule_applied --project javert \
  --agent java-developer --task "xxx" --rule rules/java.md \
  --detail "规则 3 防止了 Map 滥用，本次直接生效"

# 遇到没有规则覆盖的情况：
agency feedback --kind rule_gap --project javert \
  --detail "SSE 重连场景没有规则约束，团队出现两种实现"
```

### 提案（反馈累积到值得固化时）

```bash
agency propose --type rule-add --title "新增 SSE 重连幂等规则" \
  --evidence "javert 项目 OCR 流水线：SSE 断开重连出现重复推送，无规则覆盖" \
  --impact "java-developer / ai-engineer"
```

### 评审（每周一次，10 分钟）

```bash
agency review      # 看简报：待评审提案 + 近期反馈 + 指标
```

由 `agency-curator` 按 `workflows/evolution-review.md` 执行：打回无证据的、合并有证据的、破坏性变更找你人工确认。合并后自动要求：validate 通过 → CHANGELOG → bump 版本 → 提案入 archive。

### 守门（提交前）

```bash
agency validate    # 规范库自身：FAIL=0 才允许合并；CI 里也跑（.github/workflows/validate.yml）
agency check       # 业务仓库：增量规范门禁（hook / CI）；不要用 --all 卡存量
```

## 6. 多工具统一

- **Cursor**：读项目 `AGENTS.md` + `.cursor/rules/agency-router.mdc`；写代码任务自动匹配 `agency-route` 技能。见 `adapters/cursor.md`。
- **Codex**：读项目 `AGENTS.md` 规范路由段。见 `adapters/codex.md`。
- **Reasonix**：把 Agent 定义作为角色/Profile 来源。
- **DeepSeek Harness**：见 `adapters/deepseek-harness.md`。

工具是运行层，Agency 是规范层 —— **不要把 Agent Prompt 复制到工具自己的配置目录**。

## 7. 常见问题

| 问题 | 解决 |
| --- | --- |
| 不想记 agency 命令 | 正确：直接下任务。路由靠 AGENTS.md / Cursor 规则 / 技能自动生效 |
| 怎么知道规范有没有被用到 | 见 §2.1。第一行 `agency-route:` 且写代码时 `opened=` 为真实打开的原文 |
| 门禁怎么做 | 见 §2.2。`agency check --install`；只卡增量；默认三项 |
| 存量违规怎么办 | 见 §2.3。`--all` 出台账，不要进 hook |
| 换电脑 / 移动 workspace | 相对软链接自动跟随；业务仓库若已提交路由段，clone 即用 |
| 某个项目 AGENTS.md 被覆盖 | 不会覆盖正文；只刷新 `agency-pin` / `agency-router` 标记之间的段 |
| 规则库被改坏了 | `agency validate` 定位；规范变更一律走分支 + PR |
| 想加项目专属规则 | 写进项目自己的 AGENTS.md，不要塞中央 Agency |
| 提案没证据被打回 | 补 `--evidence`（项目 + 任务 + 观察），重新评审 |
| 想删/留某条硬规则 | 看 `docs/规则清单.md`，按编号回复 |
