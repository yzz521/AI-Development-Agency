# Security Rules

## 摘要（注入用）

- 默认最小权限；密钥不进日志（不进源码见 `rules/global.md`）。
- 所有外部输入视为不可信；SQL 必须参数化。
- API 必须认证、授权和输入校验。
- 授权要校验**数据归属**（这条记录属不属于当前用户），不只校验"已登录"。
- 用户提供的 URL 必须白名单（SSRF）；上传限类型大小；响应体脱敏。

## 全文

1. 默认最小权限。
2. 秘钥不进日志；不进源码见全局规则。
3. 所有外部输入都视为不可信。
4. SQL 必须参数化。
5. API 必须进行认证、授权和输入校验。
6. 安全问题按 Blocker / High / Medium / Low 分级并明确修复建议（安全审查任务必做，写代码任务不默认展开）。
7. 每个涉及资源 ID 的接口必须校验**数据归属**：当前用户是否有权访问这条记录。
   只校验"已登录"就是越权漏洞——这是最常见、也最容易被漏掉的一类。
8. 禁止直接请求用户提供的 URL（SSRF）。外部地址、回调地址、webhook 目标必须走白名单。
9. 禁止反序列化不可信数据：Java 原生反序列化、Python `pickle`、`yaml.load`（非 `safe_load`）。
10. 文件上传必须限制类型与大小，存储路径与执行目录隔离，并重命名后存储（不信任原始文件名）。
11. 响应体不得返回密码哈希、完整证件号、密钥、内部堆栈；按需脱敏（`138****1234`）。
12. CORS 禁止 `Access-Control-Allow-Origin: *` 与 `credentials` 同时开启。

医疗数据访问审计、敏感日志字段见 `rules/healthcare.md`，仅医疗项目加载。
