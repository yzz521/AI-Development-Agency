# Python Rules

## 摘要（注入用）

- 优先明确类型和函数职责；AI / OCR / RAG 与 Web API、数据处理解耦。
- 外部调用必须有超时、重试、错误分类和日志。
- 长任务考虑幂等、断点、重试和资源释放。
- 不裸 `except:`、不用可变对象作默认参数、不对输入用 `eval`/`exec`。

## 全文

1. 优先明确类型和函数职责。
2. AI / OCR / RAG 代码与 Web API、数据处理逻辑解耦。
3. 外部 API / 模型调用必须考虑超时、重试、错误分类和日志。
4. 密钥、模型地址、环境差异不写死（见全局红线）。
5. 长任务要考虑幂等、断点、重试和资源释放。
6. 若输出进入医疗业务链路，遵守 `rules/healthcare.md`（结构化校验、可追溯、不得覆盖确定性规则）。
7. 不用裸 `except:`。它会连 `KeyboardInterrupt` / `SystemExit` 一起吞掉，且掩盖真实异常类型；
   捕获具体异常，无法处理时至少记日志后重新抛出（`raise ... from e` 保留链路）。
8. 不用可变对象作默认参数（`def f(x=[])` / `{}`）。默认值在函数定义时求值一次，所有调用共享
   同一实例，会跨请求串数据；需要时用 `None` 哨兵，函数体内再建。
9. 不用 `eval()` / `exec()` 处理外部输入——等价于代码注入。确需动态求值时改用受限解析或白名单。
   注意 `model.eval()` 这类方法调用不受此约束。
